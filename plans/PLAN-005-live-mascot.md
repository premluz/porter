# PLAN-005 — Live mascot

## What Prem asked for (2026-10-13)

Use the Rios Brand mascot (the version with no legs or arms and capsule eyes, `http://127.0.0.1:4310/#mascot`) as the base. Make its eyes animated and expressive, following the mouse cursor. Make the body morph like a liquid, so it can split, for example into two agents. Later it will drive authored animations too, so the system must be modular. Rios Brand is where the additions are integrated.

## What exists (read 2026-10-13)

Rios Brand (`~/Rios Brand`, React 19 + TypeScript + three.js, pnpm, Vite on port 4310) has a Mascot Studio under `src/tools/mascot/`. It is a still-pose editor: `definition.ts` (all proportions, palettes, seven expressions as eye-opening and brow records), `pose.ts` (validate and clamp), `rig.ts` (eyes, limbs, gaze limited to a disk), `geometry.ts` and `scene.ts` (a 3D ellipsoid body with surface-mounted eyes, rebuilt on every pose change), WebGL and SVG renderers. Appearance switches give the Porter look: hands and legs hidden, capsule eyes, soft 3D glow. Its house rules: strict types, files ≤ 200 lines, functions ≤ 40, no inline styles, pnpm only with exact pins and a seven-day age gate, unit, browser and pixel tests. It was not under version control; it now is (`git init`, baseline commit `be6f0bd`, 2026-10-13).

Why the studio is not the runtime: it rebuilds the whole mesh per pose and has no animation loop by design; a 3D ellipsoid cannot flow or split; and three.js cannot run inside Porter's native panel. What is reused is the character (look, proportions, expression vocabulary) and the discipline.

## Architecture

```
Rios Brand (source of truth)                                   Porter (consumer)
 definition.ts ──► spec exporter ──► mascot-spec.v1.json ───copy──► Resources/mascot-spec.v1.json
                                     parity fixtures (JSON) ──copy──► Tests/…/MascotParity/*.json
 animation core (TS) ◄── same fixtures ──►                         animation core (Swift)
 liquid field (TS)                                                 LiquidField / ContourTracer (exists, ADR-007)
 Live mascot tool (#mascot/live, WebGL shader)                     Docked face (SwiftUI)
 Motion Studio keyframes (later)
```

1. **Character spec (data, versioned).** One JSON document generated from `definition.ts`, never hand-edited: palettes; body radius and squash; eye style (capsule or round with pupils), eye spacing, size and gaze travel; each expression as numbers (eye opening left/right, eye squash, eye tilt, brow, body squash); motion constants (gaze spring response and damping, blink interval range and duration, breath period and depth, expression blend time); liquid constants (fusion radius, split distance, neck time). A schema and a version number; Porter refuses a version it does not know (fail loud).
2. **Animation core (pure, two implementations, one behaviour).** `step(state, input, dt) → state`, no drawing, no clock, a seeded random source:
   - *Gaze*: the target is the cursor's direction from the character, mapped to the gaze disk; a critically damped spring follows it; small saccades when the target is still; eyes converge slightly when the cursor is close; at rest the gaze drifts back to centre.
   - *Blink*: random intervals from the spec, a quick close and open; both eyes together, an occasional double blink; no blink during a strong expression change.
   - *Expression*: a target expression from the caller (for Porter, from the agents' state); parameters blend over the spec's blend time; a short squash-and-stretch on change.
   - *Breath*: a slow body squash so it never looks frozen.
   - *Agents*: a target count (1 to 3). Going from one to two moves two blobs apart while the fusion radius falls, so a neck forms and snaps; merging runs it backwards. Each blob has its own eyes, gaze and expression.
   - Written in TypeScript in Rios Brand and in Swift in Porter. **Parity fixtures** (input sequences and expected state at sample times, generated by the TypeScript core) are run by both test suites; a Swift result off by more than a small tolerance fails. This is how two implementations stay one behaviour without sharing code.
3. **Liquid body.** The body is a distance field: each agent a rounded blob, all joined by the gradient-aware smooth minimum Porter already uses (ADR-007). Shading for the "3D glow" comes from the field's surface direction (as the WebGL demo does), so it matches the studio's upper-left light. Eyes sit on each blob's upper part and follow its squash.
4. **Renderers.**
   - Rios Brand: a new tool route `#mascot/live` with a full-screen fragment shader (raw WebGL through the three.js already installed; no new dependency) that draws the field and eyes; the page shows cursor following, an agents control (1–3), an expression picker, palette, and "reduce motion".
   - Porter: the docked face draws the blobs with the existing `LiquidField`/`ContourTracer` path and capsule eyes from the spec. The cursor position comes from `NSEvent.mouseLocation` (no permission), sampled only while the face is visible and the pointer moved; the loop runs at most at the display rate while something is moving and stops when everything has settled; Reduce Motion turns off gaze following, breath and split animation (state changes become cross-fades).
   - Porter's state mapping (initial): nothing happening → neutral, slow blinks; working → curious, eyes scanning; needs you → surprised, a bounce; just completed → happy; listening (PLAN-004) → eyes up; two or three agents working → the body splits into that many blobs, each with its own state.
5. **Later: authored animation.** Motion Studio gains keyframes on the same parameters (gaze, expression, agents, palette) and plays them through the same core, so a Rios video and Porter's tab move alike.

## Rules for agents working in Rios Brand

Follow its README and `docs/ARCHITECTURE.md`: pnpm only, no new dependency without Prem's approval, strict types, files ≤ 200 lines and functions ≤ 40 (`pnpm check`), no inline styles, CSS tokens. New modules go under `src/tools/mascot-live/` (or `src/tools/mascot/live/` if the registry needs it under Mascot); the existing studio stays untouched except for exporting from `definition.ts`. Commit each task in Rios Brand's own git repository. Run `pnpm build`, `pnpm test`, and the relevant browser and visual tests before reporting.

## Risks and open points

- Two implementations can drift: the parity fixtures are the guard; any change to the core changes the fixtures in the same commit.
- A continuously animated tab costs CPU and battery: the loop stops when settled; measure idle and following cost in Porter before shipping (FACT).
- Cursor following at a 16-point face reads only as a small eye shift; the tab may need to grow slightly. Prem's call after seeing it.
- The character is still a study pending identity review (Rios `docs/CHARACTER.md`); the spec carries its version so a redesign is a new spec, not silent drift.
